下面这份按你当前工程来写，目标是：**实机从传感器、建图、保存地图、重定位到 Nav2 导航完整跑通**。我会把需要改的文件、参数作用、怎么判断改对了都列出来。

**整体链路**
你的工程实机导航链路大概是：

```text
Livox MID360
  -> /livox/lidar + /livox/imu
  -> FAST-LIO
  -> /Odometry + /cloud_registered
  -> lio_interface
  -> /registered_scan + /registered_odometry
  -> sensor_scan_generation
  -> /odom + TF: odom -> base_footprint
  -> pointcloud_to_laserscan
  -> /scan
  -> KISS/GICP relocalization
  -> TF: map -> odom
  -> Nav2
  -> /cmd_vel
  -> 底盘驱动
```

实机部署必须保证这棵 TF 树成立：

```text
map -> odom -> base_footprint -> chassis -> livox_frame
```

如果这棵树断了，典型现象就是：RViz 报 transform 错、能出 path 但车不动、重定位看似正常但导航偏。

**1. 实机启动前先改 FAST-LIO**
文件：

[mid360.yaml](src/localization/FAST_LIO/config/mid360.yaml)

重点参数：

```yaml
common:
  lid_topic: "/livox/lidar"
  imu_topic: "/livox/imu"
```

作用：FAST-LIO 订阅的雷达和 IMU 话题。  
实机检查：

```bash
ros2 topic list | grep livox
ros2 topic hz /livox/lidar
ros2 topic hz /livox/imu
```

如果你的驱动话题不是 `/livox/lidar`、`/livox/imu`，这里要改成实际话题。

```yaml
preprocess:
  lidar_type: 5
```

你文件里注释写了：

```yaml
# 实机用：4, Gazebo用：5
```

所以实机部署时建议改成：

```yaml
lidar_type: 4
```

作用：告诉 FAST-LIO 输入点云/雷达数据格式。仿真和实机格式不同，这个错了会导致建图异常、点云畸变、里程计不稳定。

```yaml
preprocess:
  blind: 0.5
```

作用：雷达近距离盲区，单位米。小于这个距离的点会被丢掉。  
怎么调：

- 雷达离车体很近、车壳点云很多：调大，比如 `0.6`、`0.8`
- 需要看近处障碍物：不要调太大
- MID360 实机常见先用 `0.3 ~ 0.8` 试

```yaml
mapping:
  det_range: 100.0
```

作用：FAST-LIO 使用的最大感知距离。室内可以设小一些，比如 `40.0` 或 `60.0`，减轻计算压力。

```yaml
mapping:
  extrinsic_est_en: true
  extrinsic_T: [ -0.011, -0.02329, 0.04412 ]
  extrinsic_R: [ 1., 0., 0.,
                 0., 1., 0.,
                 0., 0., 1.]
```

作用：这是 **LiDAR 和 IMU 之间的外参**，不是雷达到车体的外参。

怎么选：

- 如果 MID360 内置 IMU，且你用的是标准驱动，可以先保持当前值测试。
- 如果你明确知道雷达和 IMU 的标定外参，建议：
  ```yaml
  extrinsic_est_en: false
  extrinsic_T: [你的标定值]
  extrinsic_R: [你的标定值]
  ```
- 如果外参不确定，可以先 `true`，让 FAST-LIO 在线估计，但实机稳定性可能受运动质量影响。

```yaml
map_file_path: "src/me_nav2_bringup/pcd/fast_lio_map.pcd"
```

作用：`save_pcd.sh` 保存点云地图的位置。  
这个我已经帮你统一到 `fast_lio_map.pcd` 了。实机建图后保存 PCD，就会写这里。

**2. 修改机器人和雷达安装位置**
文件：

[gld_robot_description.urdf](src/gld_robot_description/model/gld_robot_description.urdf)

当前关键位置是：

```xml
<joint name="chassis_to_livox_frame" type="fixed">
  <parent link="chassis"/>
  <child link="livox_frame"/>
  <origin xyz="0.0 0.0 0.0" rpy="0 0 0"/>
</joint>
```

这里必须改成你实车雷达相对底盘的位置。

坐标约定通常按 ROS：

```text
x: 车头前方为正
y: 车体左侧为正
z: 向上为正
rpy: roll pitch yaw，单位是弧度
```

例子：雷达在车体中心前方 `0.18m`，右侧 `0.02m`，离地 `0.32m`，朝向和车头一致：

```xml
<origin xyz="0.18 -0.02 0.32" rpy="0 0 0"/>
```

如果雷达反装，朝后，yaw 大概是 `3.14159`：

```xml
<origin xyz="0.18 0.0 0.32" rpy="0 0 3.14159"/>
```

改完后重新编译：

```bash
cd $WORKSPACE_ROOT
colcon build --symlink-install --packages-select gld_robot_description
source install/setup.bash
```

验证：

```bash
ros2 run tf2_ros tf2_echo base_footprint livox_frame
```

能持续输出，并且 xyz/rpy 接近你的实测安装值，就是对的。

**3. 如果你的底盘叫 base_link 怎么办**
你这个工程当前统一用的是 `base_footprint`：

- Nav2 用 `base_footprint`
- slam_toolbox 用 `base_footprint`
- KISS 重定位用 `base_footprint`
- sensor_scan_generation 默认用 `base_footprint`

所以建议实机也保留：

```text
base_footprint -> chassis -> livox_frame
```

如果你的底盘驱动只发布 `base_link`，不要到处乱改。更稳的做法是在 URDF 里加一个固定变换：

```xml
<link name="base_footprint"/>
<link name="base_link"/>

<joint name="base_footprint_to_base_link" type="fixed">
  <parent link="base_footprint"/>
  <child link="base_link"/>
  <origin xyz="0 0 0" rpy="0 0 0"/>
</joint>
```

然后其他 Nav2 配置继续使用 `base_footprint`。

**4. 点云转 2D 激光参数**
文件：

[Pointcloud2d_3d.yaml](src/me_nav2_bringup/config/Pointcloud2d_3d.yaml)

当前：

```yaml
target_frame: "livox_frame"
min_height: 0.2
max_height: 1.0
angle_min: -3.14159
angle_max: 3.14159
angle_increment: 0.0087
range_min: 0.05
range_max: 70.0
use_sim_time: false
```

参数作用：

`target_frame`：把点云转换到哪个坐标系下再切片。当前是 `livox_frame`。如果你的雷达 TF 正确，保持即可。

`min_height` / `max_height`：只保留这个高度范围内的点，生成 `/scan`。  
这个非常关键。调错会出现：

- 地面被当障碍物
- 桌子腿/墙看不到
- 机器人周围一圈全是障碍物
- Nav2 局部代价地图乱闪

建议实机初始值：

```yaml
min_height: -0.2
max_height: 0.5
```

如果 `/scan` 里地面点太多，增大 `min_height`。  
如果低矮障碍物看不到，降低 `min_height`。  
如果高处墙面/桌面干扰太多，降低 `max_height`。

`angle_increment`：2D 激光角分辨率。当前 `0.0087` 约等于 `0.5°`。  
值越小越精细，但计算越多。一般保持当前可以。

`range_min`：小于这个距离的点不要。  
实车如果车体自身点云进入 `/scan`，可以调大到 `0.15`、`0.2`、`0.3`。

`range_max`：最大激光距离。  
室内导航不建议 70 米这么大，初始可以改成：

```yaml
range_max: 20.0
```

验证：

```bash
ros2 topic echo --once /scan
ros2 topic hz /scan
```

RViz 里看 `/scan`，应该能看到墙、柱子、障碍物，不能看到大量车体自身点。

**5. Nav2 机器人尺寸和速度**
文件：

[nav2_params.yaml](src/me_nav2_bringup/config/nav2_params.yaml)

最先要改的是 footprint：

```yaml
footprint: "[ [0.21, 0.195], [0.21, -0.195], [-0.21, -0.195], [-0.21, 0.195] ]"
```

这个代表机器人外轮廓，单位米，坐标相对 `base_footprint`。

如果你的机器人：

- 前后长 `0.60m`
- 左右宽 `0.45m`
- `base_footprint` 在几何中心

那么应该改成：

```yaml
footprint: "[ [0.30, 0.225], [0.30, -0.225], [-0.30, -0.225], [-0.30, 0.225] ]"
```

这个字段在 `local_costmap` 和 `global_costmap` 里都要改，保持一致。

速度参数：

```yaml
FollowPath:
  min_vel_x: -0.26
  max_vel_x: 0.26
  max_vel_theta: 1.0
  acc_lim_x: 2.5
  acc_lim_theta: 3.2
```

作用：

- `max_vel_x`：最大前进速度
- `min_vel_x`：最小/最大倒车速度，负数表示允许倒车
- `max_vel_theta`：最大角速度
- `acc_lim_x`：线加速度限制
- `acc_lim_theta`：角加速度限制

实机第一次导航建议保守：

```yaml
max_vel_x: 0.15
min_vel_x: 0.0
max_speed_xy: 0.15
max_vel_theta: 0.5
acc_lim_x: 0.5
acc_lim_theta: 1.0
decel_lim_x: -0.5
decel_lim_theta: -1.0
```

如果你的底盘不支持倒车，一定把：

```yaml
min_vel_x: 0.0
```

同时速度平滑器也要同步改：

```yaml
velocity_smoother:
  ros__parameters:
    max_velocity: [0.15, 0.0, 0.5]
    min_velocity: [0.0, 0.0, -0.5]
    max_accel: [0.5, 0.0, 1.0]
    max_decel: [-0.5, 0.0, -1.0]
```

否则 controller 算出来一套速度，smoother 又限制成另一套，实车动作会怪。

**6. 代价地图参数**
还是在 [nav2_params.yaml](src/me_nav2_bringup/config/nav2_params.yaml)。

```yaml
obstacle_range: 2.5
raytrace_range: 20.0
```

作用：

- `obstacle_range`：多远内的障碍物会被加入代价地图
- `raytrace_range`：多远内用激光射线清除旧障碍物

实机建议：

```yaml
obstacle_range: 3.0
raytrace_range: 6.0
```

你现在 `raytrace_range: 20.0` 偏大，仿真里清残影很好，但实机室内可能没必要这么远。

```yaml
inflation_radius: 0.55
cost_scaling_factor: 3.0
```

作用：

- `inflation_radius`：障碍物外扩安全距离
- `cost_scaling_factor`：代价衰减速度，越小越保守，离障碍物越远

如果车宽较大、定位有抖动，建议：

```yaml
inflation_radius: 0.45 ~ 0.75
```

窄通道过不去，就适当降低；容易擦边，就升高。

**7. 地图文件**
2D 地图在：

[map 目录](src/me_nav2_bringup/map)

PCD 地图在：

[pcd 目录](src/me_nav2_bringup/pcd)

当前 KISS 默认使用：

```text
src/me_nav2_bringup/pcd/fast_lio_map.pcd
```

Nav2 默认地图由：

[my_nav2_launch.py](src/me_nav2_bringup/launch/my_nav2_launch.py)

里的 `map` 参数传入。

实机建议启动时明确指定地图：

```bash
ros2 launch me_nav2_bringup my_nav2_launch.py \
  use_sim_time:=false \
  map:=src/me_nav2_bringup/map/你的地图.yaml
```

KISS 也明确指定 PCD：

```bash
ros2 launch global_relocalization_kiss_matcher global_kiss_matcher_relocalization_launch.py \
  prior_pcd_file:=src/me_nav2_bringup/pcd/fast_lio_map.pcd \
  loop_overlap_threshold:=20.0
```

`loop_overlap_threshold` 作用：重定位匹配阈值。  
如果实机重定位很难成功，可以降到 `10.0` 或 `5.0`。  
如果误匹配、跳位置，就升高，比如 `30.0`、`50.0`。

**8. /cmd_vel 和底盘驱动**
这是你之前“有 path 但机器人不动”的核心排查点。

检查：

```bash
ros2 topic info -v /cmd_vel
```

正常应该看到：

- Nav2 或 velocity_smoother 是 publisher
- 底盘驱动是 subscriber

不要同时运行 GUI teleop 和 Nav2 直接发 `/cmd_vel`。  
如果你必须同时保留遥控和导航，建议接 `twist_mux`，而不是两个节点直接抢 `/cmd_vel`。

实机第一次测试，先不要给导航目标，手动发速度：

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
"{linear: {x: 0.05}, angular: {z: 0.0}}" -r 5
```

确认车能慢速前进，再测 Nav2。

6. `/cmd_vel`：确认 Nav2 输出真的接到了底盘驱动
